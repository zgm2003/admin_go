## Current runtime truth

- 架构方向：new-system-first / multi-platform-first。后端目标是一套核心能力服务 admin / app / canvas / openapi / merchant 等多个前端或平台入口。
- 当前 backend boundary truth 是 `internal/module/{capability}/transport/{platform}` + `internal/shared` + `internal/infra`；active exceptions 是产品范围决定，不是架构漂移。
- Admin behavior preservation 仍是验收标准：现有 admin URLs、DB 表名、permission codes、i18n keys、route metadata、operation log rules、queue task types、payment callback/finalizer 行为、frontend typed API contracts 不得被重构破坏。
- Future app/openapi/merchant/miniapp work，以及当前 canvas 入口扩展，必须在现有 capability 下增加或维护 `transport/{platform}`，不要创建平台前缀业务模块。
- Channel-specific verify-code TTL 已落地：email TTL 归 `mail_configs.verify_code_ttl_minutes`，SMS TTL 归 `sms_configs.verify_code_ttl_minutes`；旧 `system_settings.auth.verify_code.ttl_minutes` 已在本地 live MySQL check 中软删除。
- `admin_app` H5/LAN dev 当前仍是直连 Go backend `/api/app/v1`：runtime 默认 API base 是 `http://127.0.0.1:8080/api/app/v1`；部署或 LAN 真机调试必须用 `VITE_APP_API_BASE_URL` 覆盖为当前可访问的 Go backend origin。
- Realtime 当前是 admin WebSocket + notification fan-out + AI conversation events；AI cancel 是 REST `POST /api/admin/v1/ai-conversations/:id/messages/cancel`，WebSocket 只发 `ai.response.start/delta/completed/failed.v1`。
- Queue / scheduler 当前已有 Redis-backed scheduler lock；worker hot reload 和 DB+queue outbox 仍是 planned。
- Canvas free-generation active slice contract：`canvas_front_next` 独立 Next.js 前端只调用 `/api/canvas/v1/*`；本切片明确退休旧 AI billing 全局系统，Canvas 对话、图片、视频、音频生成统一通过后端托管 provider 免费执行，不查余额、不扣款、不写 `ai_billing_records`。backend/frontend/root gates 和本地 live DB migration/query 已验证。
- Canvas AI runtime selector 当前按智能体场景绑定取数：`/api/canvas/v1/settings` 的 `agents.text|image|video|audio` 来自启用的 `ai_agents` Canvas 专属场景（`canvas_text_generate` / `canvas_image_generate` / `canvas_video_generate` / `canvas_audio_generate`）；`scenes` 只是可用 Canvas 运行场景，不再是 billing metadata；Canvas AI 请求只提交 `agent_id` + 后端契约允许的用户内容/生成参数，provider model 由后端智能体决定；chat/video/audio transport 对客户端提交 `model`、`provider`、`api_key`、`base_url` 直接返回 bad request，不做静默忽略；audio 当前已接入 `/api/canvas/v1/ai/audios` raw blob 生成，但没有 `ai_assets` audio 类型、专用音频任务表或参考媒体上传。
- AI image persistence boundary：`internal/module/ai/image` owns Canvas image generation/history at `/api/canvas/v1/ai/images*`; data is owned by `ai_image_tasks` and `ai_image_files` with explicit `platform` / `user_id` dimensions, while `ai_runs` records only provider-attempt facts without source polymorphism. Admin 图片工作台 is retired from active HTTP/UI/menu surfaces; do not reintroduce `/api/admin/v1/ai-images*`.
- AI prompt/asset persistence boundary：Admin only manages prompts under `internal/module/ai/prompt`; Admin 素材管理 is retired. Canvas prompts/assets remain `/api/canvas/v1/prompts` and `/api/canvas/v1/assets`; `ai_assets.user_id` makes Canvas “我的素材” current-user owned, and no public/shared asset library exists. Legacy `canvas_prompts` / `canvas_assets` were backed up and retired by `20260608_ai_prompt_asset_drop_legacy.sql`; live MySQL no longer contains them.
- Canvas free-generation boundary：Canvas profile 由 `internal/module/profile/transport/canvas` 拥有 `GET/PUT /api/canvas/v1/profile`；Canvas UI 的 wallet/recharge 收费入口在旧 AI billing 删除切片中退休。payment/wallet/recharge 基础域仍保留给非本切片能力和未来会员时间制模型。
- Canvas auth/RBAC hotfix：后台菜单管理 `permissions/page-init` 默认平台字典必须包含 `admin/app/canvas`；Canvas 登录页必须读 `/api/canvas/v1/auth/login-config` 渲染 email/phone/password 登录方式，email/phone 走 `/send-code` 验证码登录并按 `allow_register` 自动开户，password 登录点击提交后再弹 slide captcha，不提供独立注册入口；`canvas_front_next` 的 `(user)` 页面由登录态 guard 保护，401 跳登录、403 显示无权限页。
